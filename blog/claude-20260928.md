## Skynet: lo que entró en `main`

Repositorio `guilu/skynet`. Un control plane para ver y gobernar lo que hacen
los agentes de desarrollo: proyectos, repositorios, trabajos, ejecuciones,
fases, agentes, prompts y eventos. Idea central: el orquestador es la fuente de
verdad, no la narración del modelo.

- **PR #1 — plan de implementación** (+319). Traduce la especificación a hitos
  M0–M6 (Fase 1), W1–W7 y S1–S7. Decisiones cerradas: Gradle Kotlin DSL
  multi-proyecto, Spring Data JDBC con SQL explícito (sin JPA), SQLite
  embebido como journal del runner, usuario único local para el MVP.
- **PR #10 — M0: cimientos y spike de Claude Code** (+4.423). Gradle 9.8,
  módulos `protocol`, `control-plane`, `runner`, `tools:fake-claude`; Spring
  Boot 4.1, Flyway `V1__baseline`, test de límites de Spring Modulith,
  Testcontainers con Postgres 16. Web Vite + React 19 + TS con oxlint. Docker
  multi-stage, compose con healthchecks y CI de tres jobs (Java, web, compose).
  - Spike: **9 sesiones reales de Claude Code 2.1.288 grabadas y saneadas**
    como fixtures (texto, herramientas, resume, fork, max-turns, permisos
    denegados, cancelación, presupuesto agotado, `--json-schema`).
    `fake-claude` las reproduce para tests deterministas.
  - Hallazgos documentados: stdin tiene que ir a `/dev/null`; el coste es
    acumulado por sesión (al reanudar o hacer fork se arrastra);
    `--max-budget-usd` **no es un límite duro**; una cancelación no emite
    línea `result`; `--json-schema` devuelve `structured_output`;
    `--max-turns` existe pero no aparece en `--help`.
  - google-java-format fijado en 1.28.0: la 1.37 falla dentro de Spotless con
    JDK 21.
- **PR #11 — M1: modelo de dominio, event store y timeline SSE** (+4.519 / −84).
  `V2__core_model.sql` con `project`, `repository`, `work_item`,
  `workflow_definition` (con `adhoc` sembrado), `workflow_run`, `stage_run`,
  `agent_run`, `prompt`, `event`, `event_sequence`.
  - Secuencia de eventos **global, sin huecos y en orden de commit**: se asigna
    bloqueando `event_sequence` hasta el commit, de modo que leer `sequence > N`
    nunca se salta un evento que confirme más tarde. La tabla `event` hace de
    outbox. Un trigger impide `UPDATE`/`DELETE`.
  - Ingestión idempotente por `source_event_id`.
  - `GET /api/events/stream`: replay del histórico + en vivo, reanuda con
    `Last-Event-ID` sin huecos ni duplicados, heartbeat cada 15 s.
  - Errores RFC 9457.
- **PR #12 — M2 pasos 1-2** (+1.105, abierta y mergeable al cierre): eventos
  normalizados, contrato HTTP runner ↔ control plane y `ClaudeStreamParser` que
  traduce `stream-json` a eventos `agent.*`. Coste guardado como `BigDecimal`.
  No cuenta como entregada.

## Takeaways

- Grabar sesiones reales antes de escribir el parser destapó comportamientos
  que la documentación no cuenta (presupuesto no duro, cancelación sin
  `result`). La CLI no hace exactamente lo que `--help` promete.
- Un timeline es tan fiable como su secuencia: si el orden es el de asignación y
  no el de commit, un lector puede saltarse eventos para siempre.
