Shipping Week: Three Repos, One Coherent Direction

Weekly Notes — June 8–14, 2026

If last week was about exploring local AI agents, this week was about building. Across three different repositories I went from ideas to merged pull requests, and a pattern emerged that I didn't fully see until I stepped back on Sunday: my projects are no longer separate experiments. They're starting to tell a single story.

Here's the honest builder's log of what actually shipped.

Backend to the Future — A Real Redesign, Not a Reskin

The lab site got a full redesign on a dedicated branch, driven by a proper design system rather than ad-hoc styling. Three things made it more than a coat of paint:

* A real design system as the source of truth, so spacing, color and typography stop being guesswork.
* A bilingual blog (Spanish/English) wired to the site's existing language toggle, so every article switches live with the rest of the UI.
* A project showcase, with TokenMeter front and center.

The most instructive moment was a bug that looked cosmetic but wasn't. A container class used a CSS `padding` shorthand (`padding: 0 28px`) that silently zeroed the vertical padding on every section using it. Tailwind's `py-*` utilities were being overridden by layer precedence, so entire sections lost their breathing room for no obvious reason. The lesson is old but keeps being true: shorthand properties don't just set what you typed, they reset everything you didn't. The whole redesign shipped as PR #1.

diegobarrioh.dev — Designing for the Person Reading It

My personal page got rebuilt with one specific reader in mind: a technical recruiter or an engineering team seeing me for the first time. That constraint changed every decision.

A lot of the week was tight visual iteration — the hero image floating unframed over the background, call-to-action buttons with real icons (CV PDF, LinkedIn, GitHub, Let's Talk), responsive behavior so the layout holds up on mobile without the hero shoving the title around. None of these are glamorous individually, but together they're the difference between "a developer's homepage" and "a page that takes itself seriously."

The CV page turned into the most interesting decision. ChatGPT had drafted a markdown redesign of my résumé, so the natural move was to render `/cv` as actual markdown rather than a hand-built page. That kept the content portable and easy to update. The CV now points at the real work: TokenMeter and Backend to the Future with live links, the Local AI Lab running on an NVIDIA RTX 3060 with 12 GB of VRAM, and the models I've actually tested there — Qwen 3.5, Gemma 3, Llama 3.1, DeepSeek R1 and Mistral Nemo. I also added akademia as a featured project, with its honest stack on the table: RAG-based question generation using OpenAI embeddings through OpenRouter, and a Stripe-backed store for buying study material.

akademia — Reading My Own Code Like a Stranger

The most uncomfortable and most valuable work of the week was pointing a senior-engineer code review at akademia and asking it to find what's actually wrong — not matters of taste, but real defects: race conditions, swallowed errors, type coercion hiding failures, dead config and dead code.

It found plenty. I worked through the findings in deliberate batches rather than one heroic commit, grouped onto a `fix/codebase-review` branch split across pull requests so each slice stayed reviewable. Then came the release discipline: aligning `develop` and `main`, doing a clean back-merge, and cutting release 1.3.0 with git flow.

The Lowlight

Not everything was smooth. Finishing the git flow release tripped on tagging — `git flow release finish` failed with `fatal: ¿sin mensaje de tag?` because the tag had no message and couldn't be created non-interactively. A small reminder that automation around git is great right up until it hits the one interactive prompt it can't answer. Worth solving properly before the next release, not improvising under pressure.

The Thread Connecting All Three

Stepping back, the week wasn't three unrelated tasks. The same ideas kept surfacing in every repo: a local AI lab on consumer hardware, AI-assisted development as the actual workflow rather than a novelty, and tools like TokenMeter and akademia that exist because I'm building in this new way. Even the division of labor was multi-model — ChatGPT drafting CV copy, Claude and Fable doing the building, each playing to its strength.

Key Takeaways

* A redesign backed by a design system is maintainable; a reskin is debt.
* CSS shorthand resets the properties you didn't set — `padding: 0 28px` is a foot-gun next to Tailwind utilities.
* Reviewing your own code as a hostile stranger surfaces the bugs your familiarity hides.
* Ship fixes in reviewable batches, not one heroic commit.
* Automation around git is only as robust as its most interactive prompt.

What's Next

The pieces are converging on their own, so the next step is to lean into it: make the local-and-cloud model workflow explicit instead of incidental, and keep each tool doing what it's best at. The site, the CV and the projects are all starting to say the same thing — and it's more interesting than any of them said separately.
