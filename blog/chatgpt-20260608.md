Building My Own Claude Code: A Week Exploring Local AI Agents

Weekly Notes — June 8–14, 2026

Over the last few months I’ve been using tools like Claude, ChatGPT and Gemini daily, but this week I found myself asking a different question:

What if I could build my own AI-powered development environment and run as much of it as possible on my own hardware?

That question led me down a rabbit hole of local models, coding agents, OAuth integrations, tool calling, infrastructure experiments and a fair amount of troubleshooting.

The Real Challenge Isn’t the Model

When people first explore local AI, the obvious question is usually:

Which model should I run?

This week reinforced a lesson I’ve been slowly learning:

The model is only one piece of the puzzle.

Running a coding assistant requires much more than loading a model into Ollama. To become useful, the model needs access to:

* Files and repositories
* Terminal commands
* Test execution
* Search capabilities
* Memory and context management
* Tool calling
* External services

In other words, the difficult part isn’t the LLM itself. It’s the harness around it.

I spent time investigating projects such as OpenClaw, Hermes Agent and Qwen-based coding environments, trying to understand how they bridge the gap between a language model and an actual software engineering assistant.

Can Local Models Replace Cloud Coding Agents?

One of my goals is to build a local AI development lab using the hardware I already own.

My current setup revolves around a machine equipped with an RTX 3060 (12 GB VRAM), which is powerful enough to run a surprising number of modern open-source models.

The challenge isn’t whether the models run.

They do.

The challenge is whether they can provide an experience comparable to tools like Claude Code.

Current observations:

* 7B and 14B coding models are very practical.
* Larger models require aggressive quantization or CPU offloading.
* VRAM remains the primary bottleneck.
* Tool integration matters more than raw benchmark scores.

The more I experiment, the more convinced I become that the future isn’t a single model but an ecosystem of specialized agents working together.

OAuth, Quotas and Agent Infrastructure

Another area I explored was how AI agents authenticate against commercial providers.

Modern agent frameworks increasingly rely on OAuth-based integrations instead of manually managed API keys.

This raises several interesting questions:

* How can agents inspect their remaining quota?
* How should they react when limits are reached?
* Can multiple providers coexist behind a common interface?
* How can usage be monitored and controlled?

These aren’t glamorous topics, but they’re essential if you’re trying to build reliable AI-powered workflows.

As AI tooling matures, operational concerns start looking surprisingly similar to traditional backend engineering.

Backend to the Future Is Becoming an AI Engineering Lab

One unexpected realization this week was that my personal projects are starting to converge.

Originally, Backend to the Future was primarily a place to showcase backend engineering work.

Today, many of the projects I spend time on involve:

* AI-assisted development
* Agent orchestration
* Local LLM infrastructure
* Cost monitoring
* Developer productivity tooling
* Experimentation with autonomous workflows

Projects such as TokenMeter and my ongoing local AI experiments are naturally pulling the site toward a different direction.

Not away from backend engineering.

Toward backend engineering for the AI era.

Solving Real Problems Still Matters

Not everything this week involved AI.

Some time was also spent dealing with practical infrastructure issues:

Mac Mini Audio Failure

A strange issue caused audio devices to disappear entirely from macOS. The Sound settings panel became unresponsive and Audio MIDI Setup refused to open.

Interestingly, the problem resolved itself while preparing a reboot, suggesting that a stuck process or service was blocking the audio subsystem.

A reminder that sometimes the most effective debugging tool remains:

Restart the thing.

Network Investigation

I also continued investigating unusual network behavior where a corporate laptop appeared to impact the performance of other devices on the home network.

Security software such as CrowdStrike, Zscaler and FortiClient remain possible suspects, although the root cause has not yet been fully identified.

Key Takeaways

If I had to summarize the week in a few points:

* The value of coding agents comes from the surrounding tooling, not just the model.
* Local AI is already practical with consumer hardware.
* Tool calling is more important than benchmark rankings.
* OAuth and quota management are becoming core infrastructure concerns.
* Backend engineering and AI engineering are rapidly converging.

What’s Next?

My next step is to continue building a development environment where local and cloud-based models can cooperate.

Rather than choosing between Claude, ChatGPT, Gemini or local models, I’m increasingly interested in creating workflows where each tool contributes its strengths.

The goal isn’t replacing developers.

The goal is building better tools for developers.

And right now, that feels like one of the most interesting areas in software engineering.
