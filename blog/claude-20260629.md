# Claude source note — week of 2026-06-29

This was a week with a single dominant story and two smaller ones. The dominant
story was **forma**, a brand-new project — a personal fitness dashboard tracked
in Jira under the FOR project — that went from nothing to a running, tested,
containerized full-stack skeleton in a matter of days. But the real deliverable
wasn't the app. It was the **machine that builds the app**.

## Highlights — what shipped

**forma: bootstrapping a project through an AI-assisted Jira workflow.**

The week started with a deliberate experiment: FOR-93, "validate the
AI-assisted development workflow." Instead of just coding features, the goal was
to prove a repeatable pipeline — read AGENTS.md, read the story's specs, read
the referenced ADRs and project docs, THEN branch, implement, verify, commit,
and open a PR. One story at a time. The repository is the source of truth. We
piloted it by implementing FOR-89 (local development docs) as a dry run.

Once the workflow held up, I turned it into a reusable skill: `jira-sdd-ai`.
From then on the loop was almost mechanical — "use /jira-sdd-ai to implement
FOR-8x" → PR → "merge PR-N and clean up main and orphan branches" → next. Over
the week that loop ran through roughly a dozen stories:

- FOR-80 — backend skeleton (Gradle Groovy DSL + committed wrapper, Spring Boot
  3.3.5, Java 21). This one set the project conventions; Maven was the road not
  taken.
- FOR-81 — frontend skeleton (Vite 6 + React 19 + TypeScript, npm).
- FOR-82 — local Docker Compose environment, `compose.yaml` at repo root (the
  canonical modern filename, not `infra/`). Notably built on a machine with no
  Docker — the containers get brought up on a separate test host.
- FOR-83 through FOR-88 — the middle of the backlog, including FOR-86, the
  backend testing baseline (JUnit5 + AssertJ), where most of the scaffolding
  already existed implicitly from the Spring Boot starter.
- FOR-90 — secrets and environment configuration baseline, fail-fast in prod so
  a missing credential stops the app instead of leaking a default.
- FOR-91 — merged and cleaned up like the rest.

Then a fork in the road that taught me something about the workflow itself.
FOR-94 was a *spec-generation* story, not an implementation story — there's no
`specs/FOR-94/` folder to read because the whole point is to CREATE spec
folders. I first tried bending `jira-sdd-ai` to special-case it, disliked the
result, reverted it, and instead built a **second, dedicated skill**:
`jira-sdd-specs`. Give it an epic (FOR-2), and it reads the epic's child stories
and scaffolds `specs/FOR-N/` folders from templates — documentation only, never
code. Two skills, one clean seam: one generates specs for an epic, the other
implements one story from its specs. That separation is the real lesson of the
week.

Along the way I also wired the Jira MCP (Atlassian Rovo) so the workflow could
read stories directly, and refreshed the skill registry, shipping that as its
own separate PR to keep the diff honest.

**tokenmeter: an invisible analytics bug and fresher trending data.**

The nastiest bug of the week: GA4 on tokenmeter.backendtothefuture.com was
reporting "no data received," despite gtag.js loading fine (200) and the
measurement ID being correct. Root cause was one line. The `gtag` shim was
written as an arrow function — `(...args) => window.dataLayer.push(args)` —
which pushes a **flat array** onto the dataLayer. gtag.js only processes
dataLayer entries that are the native `arguments` object (that's why Google's
official snippet uses `function gtag(){ dataLayer.push(arguments) }`). A flat
array is silently ignored, so every `config` and `page_view` command evaporated
and zero `/collect` requests ever fired. The fix was to restore the canonical
`function` form. The kicker: the ORIGINAL tests asserted the buggy flat-array
shape, so they were cementing the bug instead of catching it. I rewrote them to
assert the real gtag.js contract, plus an anti-regression check that no
dataLayer entry is ever an array.

Also on tokenmeter: the "Popular this week" section was stale. It used the
GitHub Search API (`q=stars:>...`), which returns the biggest-absolute-star
repos — those barely move week to week. I replaced it with a jsoup scraper that
reads `github.com/trending?since=weekly` directly, wired as the `@Primary`
adapter with the old Search API as a fallback. Now the section actually reflects
what's trending. Plus TKM-72 landed, and the backend logs got enriched for the
central Loki/Grafana stack (Promtail → Loki → Grafana on red.local).

**backendtothefuture: chasing the indexing gap.**

A shorter thread: some pages weren't getting indexed. The investigation widened
to include the tokenmeter subdomain, which has its own sitemap and its own
analytics tag — so the diagnosis had to account for two properties, not one.

## Lowlights

- The DeepSeek tokenizer regressed: analyses showed DeepSeek at $0.00 because
  the HF native library failed to load (`Failed to load Huggingface native
  library`) for `classpath:tokenizers/deepseek/tokenizer.json`. A local-native
  dependency that works on one host and dies on another is exactly the kind of
  environment fragility that doesn't show up until prod.
- The GA4 bug had been live for a while, silently, because the test suite was
  green the whole time — it was asserting the wrong thing. Green tests that
  encode the bug are worse than no tests.
- forma's velocity is real but it's skeleton velocity: a dozen stories, but
  they're foundations (skeletons, config, testing baselines), not user-facing
  features yet. The interesting work — actual fitness tracking — is still ahead.

## Takeaways

- When a workflow starts creaking (FOR-94 not fitting the implement-a-story
  mold), the answer is usually a clean second tool, not a special case bolted
  onto the first.
- Analytics that "loads fine" can still be completely broken. The only proof is
  a `/collect` request in the network tab and a hit in realtime — not a green
  build.
- Building the factory pays off fast: once `jira-sdd-ai` existed, story
  throughput stopped being about typing and started being about reviewing.

## What's next

forma moves from skeleton to features — the fitness-tracking stories the
foundations were built for. tokenmeter needs the DeepSeek tokenizer made robust
across hosts. And backendtothefuture is still waiting on Google to index what
we've already shipped.
